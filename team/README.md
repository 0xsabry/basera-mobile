## How each presenter prepares

1. Open the repository URL above.
2. Open your numbered topic folder.
3. Give your AI assistant the folder's `README.md` and `SOURCE_MAP.md` (paste
   them, or share the repository link and the folder path).
4. Ask it to explain the **actual code** and prepare your presentation from
   those files — exact source files, functions, and behavior, not guesses.
5. Verify every explanation against the original source files named in
   `SOURCE_MAP.md` before you present it.

## What is inside every folder

| File | Purpose |
|---|---|
| `README.md` | Topic overview, scope, duration, links to shared documentation |
| `SOURCE_MAP.md` | Exact source files, functions, components, services, APIs, tables, tests |
| `CODE_WALKTHROUGH.md` | Authentic code excerpts with exact paths, explained in simple Egyptian Arabic |
| `PRESENTATION.md` | Timed presentation script (Egyptian Arabic, technical terms in English) |
| `DEMO_GUIDE.md` | Practical demonstration steps, expected behavior, failure fallback |
| `EXPECTED_QUESTIONS.md` | Likely instructor questions with technically accurate answers |

## Honesty rules for every section

- The source code in this repository is the truth. If a document and the code
  disagree, the code wins.
- "Implemented in source code", "deployed to production", and "verified on a
  physical device" are three different states. Do not merge them when you
  present.
- Future or placeholder work (for example the smart-glasses input) must be
  presented as future work, never as a working feature.
